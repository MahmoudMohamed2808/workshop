# Filament v5 — Admin Panel Resource Structure
### Appliance Repair Workshop Management System

---

## Resource Tree Overview

```
app/Filament/Resources/
├── CustomerResource
├── DeviceTypeResource
├── BrandResource
├── DeviceModelResource
├── ProblemResource
├── RepairOrderResource        ← core resource, most complex
├── SparePartResource
├── InvoiceResource
├── PaymentResource
├── WarrantyResource
├── WhatsappMessageResource
├── UserResource               ← via Filament Shield
└── RoleResource                ← via Filament Shield

app/Filament/Pages/
├── Dashboard                  (default, customized with widgets)
└── RepairOrdersBoard          (custom Kanban-style board by status)

app/Filament/Widgets/
├── TodayOverviewWidget
├── LowStockPartsWidget
└── PendingApprovalsWidget
```

---

## 1. CustomerResource

**Relation Managers**
- `RepairOrdersRelationManager` — all repair orders for this customer
- `InvoicesRelationManager` — invoices across all their orders (via belongsToMany/through)
- `WhatsappMessagesRelationManager` — message history sent to this customer

**Custom Pages**
- `ViewCustomer` — infolist showing profile + summary stats (total orders, total spent, active warranties)

**Custom Actions**
- `SendWhatsappMessageAction` — send an ad-hoc message from the customer's page
- `MergeCustomersAction` — merge duplicate customer records (optional, nice-to-have)

---

## 2. DeviceTypeResource

**Relation Managers**
- `BrandsRelationManager` — brands under this device type
- `ProblemsRelationManager` — problems scoped to this device type (not brand-specific)

**Custom Pages**
- None (standard List/Create/Edit is sufficient)

**Custom Actions**
- `ToggleActiveAction` — activate/deactivate a device type without deleting it

---

## 3. BrandResource

**Relation Managers**
- `DeviceModelsRelationManager` — models under this brand
- `ProblemsRelationManager` — problems scoped specifically to this brand

**Custom Pages**
- None

**Custom Actions**
- `ToggleActiveAction`

---

## 4. DeviceModelResource

**Relation Managers**
- `ProblemsRelationManager` — problems scoped specifically to this exact model

**Custom Pages**
- None

**Custom Actions**
- None (simple CRUD, managed mostly via BrandResource's relation manager)

---

## 5. ProblemResource

**Relation Managers**
- None (usage is tracked via pivot on Repair Orders, not managed from here)

**Custom Pages**
- None

**Custom Actions**
- `ToggleActiveAction`
- `DuplicateProblemAction` — clone a problem into another brand/model quickly
- `MergeProblemsAction` — merge two duplicate problem entries and reassign history (nice-to-have, helps keep the list clean as staff add free-text problems)

---

## 6. RepairOrderResource *(core resource)*

**Relation Managers**
- `ProblemsRelationManager` — attached problems + per-problem cost (repair_order_problems)
- `PartsRelationManager` — attached spare parts + quantity/unit price (repair_order_parts)
- `InvoiceRelationManager` — the linked invoice (one-to-one, shown as a manager for convenience)
- `PaymentsRelationManager` — payments made against this order's invoice
- `WarrantyRelationManager` — warranty record once repair is completed
- `WhatsappMessagesRelationManager` — messages sent regarding this specific order

**Custom Pages**
- `ViewRepairOrder` — infolist with status timeline/stepper, intake photos gallery, cost breakdown
- `RepairOrdersBoard` *(global custom page, not per-record)* — Kanban board grouped by status column (Received → Inspection → Waiting Approval → ... → Delivered) with drag-to-transition

**Custom Actions**
- `ChangeStatusAction` — guarded status transition (validates allowed next states per workflow)
- `ApproveAction` / `RejectAction` — customer approval decision + rejection reason capture
- `MarkBeyondRepairAction` — sets status + requires reason
- `RecordDiagnosisAction` — quick form to add technician diagnosis + attach problems in one step
- `GenerateInvoiceAction` — creates the Invoice + InvoiceItems from the order's problems/parts/labor
- `SendWhatsappUpdateAction` — send status update to customer (intake/diagnosis/ready/reminder)
- `PrintQrCodeAction` — generate/print QR sticker for the physical device
- `ConfirmDeliveryAction` — captures delivery confirmation (name/signature) + sets `delivered_at`
- `UploadPhotosAction` — quick action to add repair/delivery photos mid-workflow (in addition to the intake form)

---

## 7. SparePartResource

**Relation Managers**
- `UsageHistoryRelationManager` — repair orders that consumed this part (repair_order_parts, read-only)

**Custom Pages**
- None (a filtered "Low Stock" tab/view on the List page is enough, no separate page needed)

**Custom Actions**
- `AdjustStockAction` — manual stock correction (restock, damage write-off) with reason/notes

---

## 8. InvoiceResource

**Relation Managers**
- `ItemsRelationManager` — invoice line items (parts, labor, problems, discounts)
- `PaymentsRelationManager` — payments recorded against this invoice

**Custom Pages**
- `ViewInvoice` — infolist styled like the printable invoice, with PDF preview embedded

**Custom Actions**
- `GeneratePdfAction` — (re)generate the invoice PDF and attach via medialibrary
- `SendInvoiceWhatsappAction` — send the PDF to the customer
- `RecordPaymentAction` — quick modal to log a new payment without leaving the invoice page

---

## 9. PaymentResource

**Relation Managers**
- None

**Custom Pages**
- None

**Custom Actions**
- None beyond default CRUD (used mainly for cross-invoice search/reporting by Accountant role)

---

## 10. WarrantyResource

**Relation Managers**
- None

**Custom Pages**
- None

**Custom Actions**
- None (mostly read-only, created automatically when a repair order is delivered; kept as a resource for searching/reporting by serial number or customer)

---

## 11. WhatsappMessageResource

**Relation Managers**
- None

**Custom Pages**
- None (a status filter on the List page — pending/sent/failed — covers the main need)

**Custom Actions**
- `ResendMessageAction` — retry sending a failed message

---

## 12. UserResource & RoleResource *(via Filament Shield)*

**Relation Managers**
- None beyond what Shield scaffolds by default

**Custom Pages**
- None

**Custom Actions**
- None beyond Shield's default role/permission assignment UI

---

## Global Custom Pages (not tied to a single resource)

| Page | Purpose |
|---|---|
| `Dashboard` (customized) | Hosts `TodayOverviewWidget`, `LowStockPartsWidget`, `PendingApprovalsWidget` |
| `RepairOrdersBoard` | Kanban view across all repair orders, grouped by status |

---

## Notes

- Pivot tables (`repair_order_problems`, `repair_order_parts`, `invoice_items`) are **not** separate top-level resources — they're managed exclusively through relation managers on `RepairOrderResource` and `InvoiceResource`.
- `DeviceModelResource` can be demoted to relation-manager-only (dropped as a top-level nav item) if you find staff never need to browse models independently of a brand — keep the resource class for the modal form, just hide it from navigation (`shouldRegisterNavigation() => false`).
- Custom Actions that trigger side effects (stock deduction, WhatsApp sending, PDF generation) should call dedicated Action classes / service classes rather than logic inlined in the Filament resource, so the same logic is reusable if you later add API endpoints or the customer-facing Inertia portal.
