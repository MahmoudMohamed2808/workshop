# Models, Service Classes & Service Provider
### Appliance Repair Workshop Management System

---

## Part 1 — Eloquent Models

```
app/Models/
├── Customer
├── DeviceType
├── Brand
├── DeviceModel
├── Problem
├── RepairOrder
├── RepairOrderProblem
├── RepairOrderPart
├── SparePart
├── Invoice
├── InvoiceItem
├── Payment
├── Warranty
├── WhatsappMessage
└── User (extended from starter kit default)
```

### Customer
- `hasMany` RepairOrder
- `hasManyThrough` Invoice (via RepairOrder)
- `hasMany` WhatsappMessage
- Uses `SoftDeletes`

### DeviceType
- `hasMany` Brand
- `hasMany` Problem
- `hasMany` RepairOrder
- Scope: `active()`

### Brand
- `belongsTo` DeviceType
- `hasMany` DeviceModel
- `hasMany` Problem
- `hasMany` RepairOrder
- Scope: `active()`

### DeviceModel
- `belongsTo` Brand
- `hasMany` Problem
- `hasMany` RepairOrder

### Problem
- `belongsTo` DeviceType
- `belongsTo` Brand (nullable)
- `belongsTo` DeviceModel (nullable)
- `belongsToMany` RepairOrder (via `repair_order_problems`, pivot: `cost`, `notes`)
- Uses `HasTags` (spatie/laravel-tags)
- Scope: `active()`, `mostUsed()`
- Accessor: `default_cost_range` (formats min–max)

### RepairOrder
- `belongsTo` Customer
- `belongsTo` DeviceType
- `belongsTo` Brand (nullable)
- `belongsTo` DeviceModel (nullable)
- `belongsTo` User as `technician`
- `belongsTo` User as `createdBy`
- `belongsToMany` Problem (via `repair_order_problems`, pivot: `cost`, `notes`)
- `belongsToMany` SparePart (via `repair_order_parts`, pivot: `quantity`, `unit_price`)
- `hasOne` Invoice
- `hasOne` Warranty
- `hasMany` WhatsappMessage
- Uses `InteractsWithMedia` (spatie/laravel-medialibrary) — collections: `intake_photos`, `repair_photos`, `delivery_photos`
- Uses `SoftDeletes`
- Casts: `accessories` → array
- Scope: `status()`, `awaitingApproval()`, `underWarrantyFor(customer, serial)`
- Accessor: `status_label`, `is_under_warranty`

### RepairOrderProblem *(pivot model)*
- `belongsTo` RepairOrder
- `belongsTo` Problem

### RepairOrderPart *(pivot model)*
- `belongsTo` RepairOrder
- `belongsTo` SparePart

### SparePart
- `belongsToMany` RepairOrder (via `repair_order_parts`)
- Scope: `lowStock()`
- Accessor: `is_low_stock`

### Invoice
- `belongsTo` RepairOrder
- `hasMany` InvoiceItem
- `hasMany` Payment
- Uses `InteractsWithMedia` — collection: `invoice_pdf`
- Accessor: `is_fully_paid`

### InvoiceItem
- `belongsTo` Invoice

### Payment
- `belongsTo` Invoice
- `belongsTo` User as `receivedBy`

### Warranty
- `belongsTo` RepairOrder
- Scope: `active()`
- Accessor: `is_expired`

### WhatsappMessage
- `belongsTo` Customer
- `belongsTo` RepairOrder (nullable)
- Scope: `failed()`, `pending()`

### User *(extended)*
- `hasMany` RepairOrder as `technician` (`technician_id`)
- `hasMany` RepairOrder as `createdOrders` (`created_by`)
- `hasMany` Payment as `receivedPayments`
- Uses `HasRoles` (spatie/laravel-permission)

## Part 2 — Service Classes

```
app/Services/
├── RepairOrderWorkflowService
├── CostCalculatorService
├── InventoryService
├── InvoiceService
├── PaymentService
├── WarrantyService
├── WhatsappService
├── QrCodeService
└── ProblemUsageService
```

### RepairOrderWorkflowService
Handles all status transitions and enforces the allowed workflow graph.
- `transitionTo(RepairOrder $order, string $status): void`
- `canTransitionTo(RepairOrder $order, string $status): bool`
- `approve(RepairOrder $order): void`
- `reject(RepairOrder $order, string $reason): void`
- `markBeyondRepair(RepairOrder $order, string $reason): void`
- `confirmDelivery(RepairOrder $order, ?string $confirmedBy = null): void` — sets `delivered_at`, triggers `WarrantyService::createForRepairOrder()`

### CostCalculatorService
Recalculates and persists order/invoice totals whenever problems, parts, labor, or discount change.
- `recalculateOrderTotal(RepairOrder $order): void`
- `computeSubtotal(RepairOrder $order): float`

### InventoryService
Owns all stock mutations so deduction logic never lives inline in a Filament action.
- `deductForRepairOrder(RepairOrder $order): void`
- `restore(RepairOrder $order): void` — reverses deduction if parts are removed/order cancelled
- `adjustStock(SparePart $part, int $delta, string $reason): void`
- `isLowStock(SparePart $part): bool`

### InvoiceService
Builds and manages the invoice lifecycle from a completed repair order.
- `generateFromRepairOrder(RepairOrder $order): Invoice`
- `addItem(Invoice $invoice, array $itemData): InvoiceItem`
- `recalculateTotals(Invoice $invoice): void`
- `generatePdf(Invoice $invoice): Media`

### PaymentService
Records payments and keeps invoice balances in sync.
- `recordPayment(Invoice $invoice, array $data): Payment`
- `refreshBalance(Invoice $invoice): void`

### WarrantyService
Creates and checks warranty coverage.
- `createForRepairOrder(RepairOrder $order, int $days): Warranty`
- `findActiveWarranty(Customer $customer, ?string $serialNumber): ?Warranty`
- `isUnderWarranty(Customer $customer, ?string $serialNumber): bool`

### WhatsappService
Wraps the WhatsApp Business API provider (Twilio / Meta Cloud API / local aggregator) and logs every attempt.
- `send(Customer $customer, string $message, ?string $mediaUrl = null): WhatsappMessage`
- `sendTemplate(Customer $customer, string $type, array $data, ?RepairOrder $order = null): WhatsappMessage`
- `resend(WhatsappMessage $message): WhatsappMessage`
- `markSent(WhatsappMessage $message): void`
- `markFailed(WhatsappMessage $message, string $error): void`

### QrCodeService
Generates a printable QR code per repair order (via `simplesoftwareio/simple-qrcode`).
- `generateForRepairOrder(RepairOrder $order): string` — returns SVG/PNG content or storage path

### ProblemUsageService
Keeps the "most common problems" ordering accurate.
- `incrementUsage(Problem $problem): void`
- `mostUsedFor(DeviceType $type, ?Brand $brand = null, ?DeviceModel $model = null, int $limit = 5): Collection`

## Part 3 — Service Provider & Facades

Register every service as a singleton in one dedicated provider, and expose the ones used frequently inside Filament actions as facades for cleaner call sites (`Whatsapp::sendTemplate(...)` instead of resolving the class each time).

```
app/Providers/WorkshopServiceProvider.php
app/Facades/
├── Whatsapp.php
├── Inventory.php
├── Invoice.php
├── Warranty.php
└── RepairOrderWorkflow.php
```

**`app/Providers/WorkshopServiceProvider.php`**

```php
<?php

namespace App\Providers;

use App\Services\CostCalculatorService;
use App\Services\InventoryService;
use App\Services\InvoiceService;
use App\Services\PaymentService;
use App\Services\ProblemUsageService;
use App\Services\QrCodeService;
use App\Services\RepairOrderWorkflowService;
use App\Services\WarrantyService;
use App\Services\WhatsappService;
use Illuminate\Support\ServiceProvider;

class WorkshopServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->singleton(RepairOrderWorkflowService::class);
        $this->app->singleton(CostCalculatorService::class);
        $this->app->singleton(InventoryService::class);
        $this->app->singleton(InvoiceService::class);
        $this->app->singleton(PaymentService::class);
        $this->app->singleton(WarrantyService::class);
        $this->app->singleton(WhatsappService::class);
        $this->app->singleton(QrCodeService::class);
        $this->app->singleton(ProblemUsageService::class);

        // Facade accessor bindings (short aliases used by the facades below)
        $this->app->alias(WhatsappService::class, 'whatsapp');
        $this->app->alias(InventoryService::class, 'inventory');
        $this->app->alias(InvoiceService::class, 'invoice');
        $this->app->alias(WarrantyService::class, 'warranty');
        $this->app->alias(RepairOrderWorkflowService::class, 'repair-order-workflow');
    }
}
```

> Register it in `bootstrap/providers.php` (Laravel 11+/13 style, no `config/app.php` providers array needed):
> ```php
> return [
>     App\Providers\AppServiceProvider::class,
>     App\Providers\WorkshopServiceProvider::class,
> ];
> ```

**Example facade — `app/Facades/Whatsapp.php`**

```php
<?php

namespace App\Facades;

use Illuminate\Support\Facades\Facade;

/**
 * @method static \App\Models\WhatsappMessage send(\App\Models\Customer $customer, string $message, ?string $mediaUrl = null)
 * @method static \App\Models\WhatsappMessage sendTemplate(\App\Models\Customer $customer, string $type, array $data, ?\App\Models\RepairOrder $order = null)
 * @method static \App\Models\WhatsappMessage resend(\App\Models\WhatsappMessage $message)
 *
 * @see \App\Services\WhatsappService
 */
class Whatsapp extends Facade
{
    protected static function getFacadeAccessor(): string
    {
        return 'whatsapp';
    }
}
```

The other four facades (`Inventory`, `Invoice`, `Warranty`, `RepairOrderWorkflow`) follow the exact same pattern — same file structure, just swap the accessor string and the `@method` docblock to match that service's public methods.

| Facade | Accessor | Wraps |
|---|---|---|
| `App\Facades\Whatsapp` | `whatsapp` | `WhatsappService` |
| `App\Facades\Inventory` | `inventory` | `InventoryService` |
| `App\Facades\Invoice` | `invoice` | `InvoiceService` |
| `App\Facades\Warranty` | `warranty` | `WarrantyService` |
| `App\Facades\RepairOrderWorkflow` | `repair-order-workflow` | `RepairOrderWorkflowService` |

> `CostCalculatorService`, `QrCodeService`, and `ProblemUsageService` are intentionally left without facades — they're typically called from inside other services or observers, not directly from Filament actions, so plain dependency injection (`app(CostCalculatorService::class)` or constructor injection in an Action class) keeps things simpler there.
